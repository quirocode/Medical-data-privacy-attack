## Project Overview
This project demonstrates the critical vulnerabilities of traditional data anonymization techniques (like data masking and dropping PII) in large-scale electronic health records (EHR). By executing a **Multi-dimensional Asymmetric Linkage Attack** on a synthetic dataset of over 1.1 million medical records, this project proves that deterministic re-identification is possible by exploiting quasi-identifiers and overcoming $k$-anonymity thresholds.

**Key Achievements:**
* Processed and analyzed a Big Data ecosystem containing **+1,143,000 synthetic medical records** (Synthea COVID-19 100k Dataset).
* Applied advanced **Data Imputation** techniques to prevent survival bias in demographic data.
* Achieved an **85.05% theoretical limit of re-identification**, exposing the medical secrecy of over 972,000 simulated patients.

## Tech Stack & Methodologies
* **Language:** Python
* **Libraries:** Pandas (Data Wrangling, Joins, Merges), OS, Kaggle API.
* **Concepts:** $k$-anonymity, Linkage Attacks, Data Imputation, Dimensionality Expansion, Differential Privacy awareness.

## Methodology
1. **Data Ingestion:** Automated fetching of Big Data sets via the Kaggle API directly to a cloud environment.
2. **Data Wrangling:** Merging patient demographics with clinical conditions, mapping 1-to-Many relationships.
3. **Data Imputation:** Filling `NaN` values in critical features (Race, Marital Status) to preserve minority statistical clones.
4. **Linkage Attack execution:** Isolating unique individuals in a simulated public registry and deterministically linking them to their "anonymized" hospital records using `['BIRTHDATE', 'GENDER', 'ZIP', 'RACE', 'MARITAL', 'CITY', 'ETHNICITY']`.

## How to Run the Project
1. Clone the repository: `git clone https://github.com/tu-usuario/medical-data-privacy-attack.git`
2. Install dependencies: `pip install -r requirements.txt`
3. Setup your `kaggle.json` API token as per Kaggle's official documentation.
4. Run the Jupyter Notebook located in the `notebooks/` directory.

> **Note on Ethics:** This project was conducted strictly on **100% synthetic data** generated by Synthea. No real patient data was harmed, accessed, or exposed, ensuring compliance with ethical research standards and HIPAA concepts.
